# 音乐库体检（元数据刮削）

> 由独立刮削工具容器提供能力（仓库 `scraper/` 目录），对应[路线图](./roadmap.md)第 4 期；规划与进度看板见仓库内 `docs/META_SCRAPER_PLAN.md`。

NAS 音乐库的听感与展示质量直接取决于音频文件的内嵌元数据。音乐库体检提供：

- **问题清单**：自动扫描音乐目录，按「缺封面 / 缺歌词 / 缺专辑 / 缺歌手 / 文件名混乱 / 疑似重复」六类归类
- **在线匹配**：用文件名与现有标签搜索在线音源（酷我），给出候选与置信度分级
- **一键写入**：将选中的候选写回文件——ID3v2（mp3）/ Vorbis（flac）/ MP4（m4a）标签、内嵌封面与歌词，可选按「歌手 - 标题」重命名
- **忽略清单**：无法修正的文件不再反复提示

## 安全设计

写文件不可逆，因此工具默认全链路保守：

| 机制 | 说明 |
| --- | --- |
| dry-run 预览 | 任何写入前先展示逐字段变更清单，确认后才落盘 |
| 写前备份 | 首次写入前把原文件复制到音乐目录下 `.mc-backup/`（默认开启） |
| 置信度门槛 | 置信度 < 80% 的候选仅展示不自动选用；无歌手参照的查询最高 75%，必须人工选择 |
| 重命名保护 | 默认关闭；开启后目标文件名冲突自动跳过，不回滚写入 |
| 增量扫描 | 以文件大小 + 修改时间判断变更，重复扫描秒级完成 |

## 架构

```
[浏览器] ── 同源 /mc ──▶ [nginx / Vite proxy] ──▶ [scraper 容器]
                                                     │  /music（NAS 音乐目录卷，读写）
                                                     │  /data（SQLite：索引/任务/配置）
                                                     ▼
                                              音源后端（searchSong / getLyric）
```

- 刮削能力在**独立容器**里：文件级写操作风险隔离、可独立授权与重启（架构决策 #2 修订）
- 工具不自带音源解析，在线匹配复用音源后端的搜索与歌词接口（契约对齐 SQMusic）
- 经预留的 `/mc` 前缀同源反代访问，浏览器无跨域问题（决策 #9）

## 部署

前置：已按[部署指南](./deployment)跑起 web 容器；fnOS 音乐库目录在 Docker 内可达。

```bash
# .env 追加：
MC_MUSIC_DIR=/vol1/@team/DockerSpace/simple-sq-music-plus/music   # fnOS 音乐库目录（读写）
MC_SCRAPER_BASE_URL=http://scraper:8098
# 可选：共享 token（工具侧同样设置后前端自动携带）
#MC_SCRAPER_TOKEN=

docker compose --profile scraper up -d
```

启动后 Web 端出现「体检」入口（未配置 `MC_SCRAPER_BASE_URL` 时自动隐藏）。镜像由 CI 自动发布（`scraper-docker.yml`，与主镜像同 tag 策略，amd64/arm64 双架构）。

## 工具配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 写入策略 | 仅补空缺 | `fill-missing` 只填空缺字段；`overwrite` 用候选整组覆盖 |
| 内嵌封面 / 歌词 | 开 | 关闭后跳过对应写入 |
| 写前备份 | 开 | 备份到 `.mc-backup/`（保留原目录结构） |
| 重命名 | 关 | 模板 `{artist} - {title}`，可用 `{album} {year} {trackNo}` |
| 置信度下限 | 0.8 | 低于该值的候选仅展示，需人工选择 |
